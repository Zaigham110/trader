# Eval sets — SEEDS (D-040, LOCAL_LLM.md §7)

These three JSONL files are **seed sets written by the development team on 2026-11-05**. Every item
is **synthetic**: the headlines, bodies, sources (`seed-wire`, `seed-release`, `seed-stats`,
`seed-desk`, `seed-blog`), trades and feature rows were invented to cover the label space; **none of
the headlines is a real quote** and none describes a real release, meeting, conflict or company.
Labels were assigned by hand (headlines, reviews) or by code (regimes).

They exist so the harness (`goldtrader.evals.harness`) can be built and tested against
`FakeProvider`. Before any model or prompt change is promoted (D-040; LEARNING_SYSTEM §5) the sets
must be **extended with real items published after the candidate model's training cutoff**
(docs/research/04_learning_and_validation.md §2.1: evaluating an LLM on pre-cutoff news is
inadmissible as evidence), towards the sizes in LOCAL_LLM §7 (≈ 300 headlines, ≈ 200 regime rows,
≈ 50 reviews with a human-graded subset). Record the model cutoff with every summary you keep.

| file | items | shape |
|---|---|---|
| `headlines_v1.jsonl` | 60 | `{id, published_at, source, title, body, label: {relevance, event_type, direction_for_gold, magnitude, horizon}, pair_id?}` — every enum of `contracts.NewsEvent` at least 3 times; 10 irrelevant (`relevance: none`), 7 ambiguous (`direction_for_gold: unclear`), 8 `pair_id` pairs (p1–p8) that report the same release with the opposite surprise sign (hot / cool CPI and PCE, strong / weak payrolls and claims, hawkish / dovish FOMC, dollar up / down, GDP beat / miss, ETF inflow / outflow) for the perturbation test |
| `regimes_v1.jsonl` | 40 | `{id, features: {atr_pct_daily, rv_pctile, trend_state, spread_regime, hour_utc}, label: calm \| normal \| stress}` — generated by `goldtrader/evals/generate_regimes.py` from the thresholds in `goldtrader/data/features.py` (boundary values included); the test suite checks the file matches the generator byte for byte |
| `reviews_v1.jsonl` | 20 | `{id, trade: {...journal row...}, attribution: {signal_pnl, timing_pnl, slippage, costs}, label: outcome_class, rubric: [str]}` — every `PostMortem.outcome_class` except the code-only fallback `unreviewed` at least twice; `rubric` is for human grading only, never an automated gate |

Versioning: a set is immutable once committed; extend by adding `*_v2.jsonl` and pointing
`harness.SETS` at it so summaries stay comparable within a version.
